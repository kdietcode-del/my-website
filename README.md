# 뷰티 제품 런칭 상황판

뷰티 제품 아이디어를 모으고, 기획부터 생산까지 진행 상황을 추적하고, 경쟁 제품을 비교하는 웹 상황판입니다.
설치할 것도 서버도 필요 없습니다. `index.html` 을 더블클릭하면 브라우저에서 바로 열립니다.

## 보드 세 개

### 1. 제품 런칭 상황보드

제품마다 8단계를 따라갑니다. 각 단계에는 기본 체크리스트 6개가 들어 있고, **진행률은 체크한 항목 수에서 자동으로 계산됩니다.** 진행률을 손으로 입력하는 칸은 일부러 두지 않았습니다.

| # | 단계 | 무엇을 하는 단계인가 |
| --- | --- | --- |
| 1 | 제품 기획 | 무엇을, 누구에게, 왜 파는지 확정 |
| 2 | 제조사 미팅 | 만들어 줄 파트너를 찾고 조건을 맞춤 |
| 3 | 제형 확정 | 사용감과 전성분을 못 박고 상용화 가능한지 검증 |
| 4 | 임상 진행 | 광고에 쓸 효능을 숫자로 증명 |
| 5 | 제품 디자인 | 용기와 패키지 확정, 인쇄 발주 |
| 6 | 생산 | 본생산, 품질 검사, 입고 |
| 7 | 상세페이지 기획 | 고객을 설득할 문구와 구조 설계 |
| 8 | 비주얼 기획 | 제품이 보여질 이미지와 톤 제작 |

앞의 6단계는 물건을 만들어 내는 흐름이고, 뒤의 2단계는 그 물건을 파는 준비입니다.

8단계는 접히는 목록이 아니라 **각각 독립된 블록**으로 항상 펼쳐져 있습니다. 화면 폭에 따라 3열 → 2열 → 1열로 접힙니다.

**할 일 하나하나에 메모 칸이 붙어 있고 항상 보입니다.** 클릭해서 펼칠 필요가 없고, 내용이 길어지면 칸이 알아서 늘어납니다. 칸이 좁아지면 메모가 할 일 아래로 내려갑니다. 타이핑을 멈추면 저장됩니다.

**할 일 순서는 왼쪽 손잡이(⠿)를 끌어서 바꿉니다.** 손잡이에 커서를 두고 `↑` `↓` 키로도 옮길 수 있습니다. 손잡이를 잡았을 때만 줄이 끌리므로 메모 칸의 글자 선택은 그대로 됩니다.

각 단계마다 할 일을 추가·삭제할 수 있고, 단계 전체 메모와 목표일도 따로 남길 수 있습니다.
전체 목록 화면에서는 제품별 진행률과 8단계를 한 줄로 압축한 미니 지표를 함께 봅니다.

### 2. 경쟁제품 참고보드

런칭 준비 중인 제품별로 경쟁 상대를 모아 놓고 비교합니다.

- **가격 비교 차트** — 우리 목표 판매가를 경쟁 제품과 나란히 놓고 봅니다
- **비교 표** — 썸네일 · 가격 · 용량 · 핵심 성분 · 소구 포인트 · 판매 채널 · 메모 · 링크

**상세페이지 링크를 넣고 `링크에서 가져오기` 를 누르면 제품명 · 브랜드 · 가격 · 썸네일이 자동으로 채워집니다.** 이미 적어 둔 값은 덮지 않습니다.

이 기능만은 작은 중계 서버가 필요합니다. 브라우저가 다른 사이트의 내용을 직접 읽지 못하기 때문입니다(CORS). 설치는 [`worker/README.md`](worker/README.md) 를 보세요 — Cloudflare 무료 범위로 충분하고 10분이면 됩니다.

서버를 안 만들어도 앱은 그대로 돌아갑니다. 자동으로 못 가져오면 안내만 뜨고, 직접 입력하면 됩니다. 사이트에 따라 봇 차단으로 실패할 수 있습니다(클럽클리오 같은 자사몰은 확인됨).

여기 쌓아 둔 내용은 7단계 상세페이지 기획에서 그대로 재료가 됩니다.

### 3. 차기 신제품 아이디어

떠오른 제품 아이디어와 참고할 타사 사례를 아무렇게나 던져 두는 판입니다.

- **구분** — 내 아이디어 / 타사 레퍼런스 (카드에는 타사 레퍼런스일 때만 표시됩니다)
- **피부효능** — 미백 · 탄력 · 모공 · 결 · 트러블
- **카테고리** — 앰플 · 클렌저 · 크림 · 토너 · 마스크팩 · 바디
- **진행 상태** — 미정 · 보류 · 개발 진행
- **컨셉** — 어떤 고민을 어떻게 해결하는 제품인지
- **성분** — 핵심 성분과 함량
- **광고 소구점** — 광고에서 무엇을 어떻게 보여줄지
- **이미지** — 제품 컷, 레퍼런스 스크린샷 등을 최대 8장 (파일 또는 이미지 주소)
- **참고 레퍼런스** — 타사 제품, 아티클, 이미지 링크를 여러 개 붙일 수 있습니다
- **태그 · 메모**

피부효능과 카테고리는 각각 따로 걸러 볼 수 있습니다.

쓸 만해진 아이디어는 **`런칭 준비로 →`** 버튼 하나로 제품 런칭 상황보드에 넘어갑니다. 이때 아래 8단계 체크리스트가 자동으로 만들어집니다.

## 데이터는 어디에 저장되나요

**코드에는 회사 정보가 들어 있지 않습니다.** 이 저장소가 공개든 비공개든, 제품 아이디어와 배합은 어디에도 담기지 않습니다. 처음 여는 브라우저에는 빈 보드가 뜨고, 백업 파일을 불러오면 채워집니다.


입력한 내용은 **이 브라우저에만** 저장됩니다. 서버로 전송되지 않고, GitHub에도 올라가지 않습니다.

- 글자 정보는 localStorage 에 (약 5MB 한도)
- 이미지는 IndexedDB 에 따로 — 용량 한도가 훨씬 넉넉하고, 넣을 때 긴 변 1400px JPEG 로 자동으로 줄입니다

`백업` 으로 내려받는 JSON 파일에는 **이미지까지 함께** 담기므로, 그 파일 하나로 다른 PC에 그대로 옮길 수 있습니다.

그래서 이런 경우 내용이 사라집니다.

- 브라우저 데이터(쿠키 · 사이트 데이터)를 지웠을 때
- 다른 브라우저나 다른 PC에서 열었을 때
- 시크릿 모드에서 창을 닫았을 때

중요한 내용은 오른쪽 위 **`⚙ 설정` → `백업 파일 내려받기`** 로 받아 두세요. 다른 PC에서는 같은 곳의 **`백업 파일 불러오기`** 로 넣으면 그대로 복원됩니다.

> 백업·불러오기·샘플 지우기는 실수로 눌러 데이터가 날아가지 않도록 **설정 안에** 넣어 두었습니다. 불러오기는 지금 내용을 모두 덮어쓰므로 한 번 더 확인합니다.

## 비밀번호에 대해

`⚙ 설정` → `비밀번호` 에서 비밀번호를 정하면 `gate-config.js` 파일이 내려받아집니다. 그 파일로 `js/gate-config.js` 를 덮어쓰고 GitHub 에 올리면 그때부터 사이트가 잠깁니다. 비밀번호 원문은 어디에도 저장되지 않습니다.

**다만 이 잠금이 무엇인지 정확히 알아 두세요.**

이 사이트는 서버 없이 도는 정적 사이트라, 비밀번호 검사가 **방문자의 브라우저 안에서** 이뤄집니다. 브라우저 개발자 도구를 다룰 줄 아는 사람은 우회할 수 있습니다.

- ✅ 막아 줍니다 — 주소를 우연히 알게 된 사람, 검색으로 들어온 사람
- ❌ 못 막습니다 — 작정하고 들여다보려는 사람

**정말 막아야 한다면** 서버 단에서 인증하는 방식(예: Cloudflare Access)이 필요하고, 그러려면 GitHub Pages 가 아닌 곳으로 옮겨야 합니다.

그래서 **회사 정보는 코드에 두지 않습니다.** 비밀번호를 걸어도 파일 주소(`/js/data.js`)를 직접 치면 그대로 읽히기 때문입니다. 입력한 내용은 각자의 브라우저에만 남습니다.

## 파일 구성

```
index.html          화면 뼈대
style.css           디자인 (기본 밝게, 어둡게로 전환 가능)
js/gate-config.js   비밀번호 설정 (비어 있으면 잠금 없음)
js/gate.js          잠금 화면
js/data.js          분류 기준, 8단계 정의 (초기 데이터는 비어 있음)
js/images.js        이미지 보관 (IndexedDB, 자동 축소)
js/store.js         데이터 보관, 저장/복원, 진행률 계산
js/ui.js            공통 UI (진행률 막대, 상태 배지, 모달 폼)
js/meta.js          링크에서 제품 정보 가져오기
js/ideas.js         3. 차기 신제품 아이디어
js/pipeline.js      1. 제품 런칭 상황보드
js/competitors.js   2. 경쟁제품 참고보드
js/app.js           탭 전환, 테마, 설정, 백업
worker/             썸네일 가져오기 중계 서버 (선택, Cloudflare)
```

빌드 도구나 외부 라이브러리를 쓰지 않습니다. 파일을 고치고 저장한 뒤 브라우저를 새로고침하면 바로 반영됩니다.
